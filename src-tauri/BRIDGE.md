# Desktop bridge contract

The Rust host is a narrow supervisor. The webview cannot choose executables or
arguments and has no shell, dialog, or opener plugin permissions. All product
logic remains in `python/aistereo`.

## Frontend invokes

- `runtime_info() -> { mode: "tauri", platform, workerReady, version, ... }`
- `pick_video() -> string | null`
- `default_project_base() -> "D:\\Parallax Projects"`
- `pick_project_base_directory() -> string | null`
- `plan_new_project({ sourceVideo, baseDirectory? }) -> NewProjectPlan`
- `allocate_new_project({ sourceVideo, baseDirectory? }) -> NewProjectPlan`
- `pick_project_directory() -> string | null`
- `save_output({ suggestedName, extension }) -> string | null`
- `authorize_preview_asset({ path }) -> string`
- `worker_request({ request }) -> { accepted, id, workerPid }`
- `cancel_job({ jobId }) -> { accepted, id, workerPid }`
- `restart_worker() -> WorkerSnapshot`
- `stop_worker() -> boolean`
- `reveal_output({ path }) -> void`
- `llm_key_status() -> { configured, source, securePersistentStorage, workerRestartRequired }`
- `save_llm_key({ apiKey }) -> LlmKeyStatus`
- `has_llm_key() -> boolean` (never returns the key)
- `delete_llm_key() -> LlmKeyStatus`

Compatibility aliases are `choose_video_file`, `choose_project_folder`, and
`send_worker_command`. Dedicated `create_project` and `open_project` commands
also exist, but new frontend code should use `worker_request`.

`plan_new_project` and `allocate_new_project` return camel-case fields
`sourcePath`, `sourceName`, `baseDirectory`, `projectDirectory`, `projectName`,
`folderName`, `collisionIndex`, and `created`. Planning is read-only.
Allocation atomically creates exactly one empty video-named child and never
reuses or overwrites a path: collisions advance from `Name` to `Name (2)`,
`Name (3)`, and so on. Omitting `baseDirectory` uses the application-owned
default `D:\Parallax Projects`. A custom base must first be selected through
`pick_project_base_directory` in the current native session.
`collisionIndex` is `0` for the preferred unsuffixed name and otherwise matches
the visible suffix (`2` for `Name (2)`). `projectName` is the final unique
`folderName`, so colliding projects remain distinct in markers and recent lists.
Planning and allocation dispatch filesystem inspection to Tauri's blocking-task
pool so an unavailable custom drive cannot stall the desktop UI thread.

`worker_request.request` is a JSONL request:

```json
{"id":"preview-4f4f38d7-35e8-4a42-90e8-79f5d43fac66","method":"render_preview","params":{"project_dir":"C:\\Projects\\Demo","shot_id":12,"depth_backend":"video-depth-anything-small","device":"auto","allow_fallback":true}}
```

Only the product method enum and each method's exact parameter schema in
`protocol.rs` are accepted. Required fields, enum vocabularies, numeric bounds,
payload size, nesting, and path-bearing parameters are validated. `config_path`,
provider credentials, arbitrary model names, and unknown fields are rejected.
Request and cancellation IDs must use the expected operation prefix plus a UUID
v4 generated by the app. Video files, project roots, caches, and output targets
must first be granted by the corresponding native picker. A project selection
must be empty or contain a valid bounded `project.json` marker.

A project-storage base is not a project-root grant. Native state records custom
bases separately, and neither the default base nor a selected custom base gives
the worker recursive access to existing contents or sibling projects. Only the
new collision-free child and its already picker-approved source video are
granted and bound together. Project folder names are derived in Rust, bounded,
and sanitized for Windows-invalid characters, controls, trailing dots/spaces,
and reserved device names; the webview cannot provide a folder name.

`allow_fallback` is accepted by depth estimation, feature extraction, direction,
and shot preview. Passing it through those preview-analysis requests makes every
dependent stage reuse the same resumable depth fingerprint, including a
synthetic per-shot fallback. Final render methods reject the parameter and still
require current, certified production depth.

Picking a project does not grant recursive asset-protocol access. The frontend
must call `authorize_preview_asset` for each generated media file immediately
before `convertFileSrc`; Rust canonicalizes it, checks a media extension and the
active path policy, and scopes only that exact file. JSON, logs, and arbitrary
project artifacts cannot be converted to asset URLs.

The optional LLM key is never returned to JavaScript and never crosses JSONL.
On Windows it is persisted in Windows Credential Manager under the app service
name. Rust injects it only as `AISTEREO_LLM_API_KEY` while spawning the worker.
Saving or deleting a key stops a running worker after the credential operation,
so the next request starts a child with exactly the current environment and no
app-owned child retains a replaced key. Other platforms are environment-only
until their native stores are certified.

## Events

Listen on `worker-event`. The event detail is one typed Python event, unchanged
apart from schema validation:

- `{ type: "progress", id, job_id, stage, completed, total, message? }`
- `{ type: "result", id, result }`
- `{ type: "error", id, error: { code, message, details?, retryable } }`
- `{ type: "log", id?, level, message }`

Malformed, oversized, or impossible events with a valid request ID are replaced
with a bounded request-scoped `invalid_worker_event` error, so the UI can finish
the request. Uncorrelated protocol failures become generic host logs. Release
builds never relay raw worker stderr; debug diagnostics are bounded and redact
the exact loaded credential plus `Bearer` and `sk-...` patterns. Stdout remains
protocol-only and event objects reject unknown fields.

## Worker launch

Debug builds run the fixed command `python -u -m aistereo.worker` from the
repository root, prepend `python/` to `PYTHONPATH`, and optionally honor the
developer-only `AISTEREO_PYTHON` interpreter path. Release builds can execute
only the configured one-file `aistereo-worker` Tauri sidecar. Release launch also
resolves package-owned FFmpeg and ffprobe resources, supplies their exact paths,
and puts their directory first on the child PATH. A reviewed depth adapter is
supplied only after its build-embedded SHA-256 passes a one-time startup check;
the webview cannot provide any executable, configuration, or model path. See
`binaries/README.md` for staging. The process starts lazily, is serialized across
concurrent requests, and is killed on explicit stop/restart and application exit.
